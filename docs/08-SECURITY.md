# 08 · Безопасность

## Уровни защиты

### 1. Telegram-бот — AuthMiddleware
- Владелец (`USER_ID=<YOUR_TELEGRAM_ID>`) авторизован автоматически через `.env`
- Другие пользователи получают доступ по коду из `ACCESS_CODE` в `.env`
- Авторизация хранится in-memory (`AUTH_USERS` set) — при перезапуске контейнера сбрасывается
- Middleware зарегистрирован глобально на уровне Dispatcher (message + callback_query)

### 2. Caddy — IP allowlist
- Все поддомены `*.example.com` защищены IP-фильтрами:
  - LAN брата: `192.168.1.0/24`
  - IPv6: `fdXX:XXXX:XXXX::/64`
  - WireGuard VPN: `10.10.10.0/24`
  - Localhost: `127.0.0.1/32`
- Публичный интернет → `403 Forbidden`
- z2m.example.com дополнительно защищён basic-auth (bcrypt)

### 3. WireGuard — шифрованный туннель
- Единственный путь из интернета к принтерам: через WG-туннель atlas→routerich
- Все пакеты зашифрованы, аутентификация по ключам

### 4. SSH — только ключи
- Парольная аутентификация отключена на atlas (`PasswordAuthentication no`)
- Hardening через `/etc/ssh/sshd_config.d/00-hardening.conf`
- Файл `50-cloud-init.conf` может тихо включить `yes` — следить!

### 5. Firewall (UFW на atlas)
- Открыто наружу: 22 (SSH), 80/443 (Caddy), 51820 (WireGuard)
- Принтеры не имеют прямого доступа из интернета

## Правила работы на сервере atlas

> **Сервер боевой и живёт 24/7.** Умный дом, VPN, файлы. Необдуманное изменение → гаснет свет в квартире.

### 10 мандатов:
1. **Сначала прочитай, потом меняй.** Не угадывай конфиги — проверь (`cat`, `docker ps`, `wg show`)
2. **Verify после каждого изменения.** Не заявляй «готово» без вывода команды
3. **Идемпотентность и обратимость.** `grep -q ... || append`, знай откат
4. **Деструктивные операции — только с подтверждением.** `rm`, `reboot`, firewall — озвучь и дождись «да»
5. **Не ослабляй периметр.** Не открывай порты, не отключай fail2ban
6. **Бэкап перед рискованным.** `cp file file.bak-$(date +%F)`
7. **Одно изменение за раз.** Не накатывай пачку без промежуточной проверки
8. **WireGuard — правь руками.** `wg-quick save` стирает PostUp/PostDown NAT-правила
9. **Секреты не в репозиторий.** Пароли, ключи — только на сервере/.env
10. **Docs = source of truth.** Обновил сервер — обнови `docs/*.md` в том же заходе

### Git-коммиты
- Язык: английский
- Формат: Conventional Commits (`feat`/`fix`/`docs`/`refactor`/`chore`)
- Doc-gate: перед каждым коммитом — проверить, какие docs нужно обновить

|--------|-------------|---------------------|

## Политика «Не замусорить сервер»

Пользователь явно формулирует правило:
> «Прежде чем что-то менять, сначала скажи, что хочешь сделать. Главное — не сломать сервер и не замусорить его архитектуру.»

### Практическое применение:
1. Любое изменение на сервере atlas — **сначала план → одобрение → выполнение → verify**
2. Не добавлять лишние контейнеры, порты, сервисы без явной необходимости
3. Не модифицировать чужие (admin) конфиги без согласования
4. При откате — использовать `git revert` (чистая история), а не force-push
